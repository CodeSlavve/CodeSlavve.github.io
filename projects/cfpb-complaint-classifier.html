CFPB Complaint Classifier

An end-to-end NLP system that predicts one of eight CFPB product categories from a consumer complaint narrative.

Try the live demo

Overview

The project uses a balanced sample of 50,000 CFPB complaints, with 6,250 examples in each of eight selected product categories. Its production classifier is served by a deployed FastAPI service.

The data is split into 35,000 training, 7,500 validation, and 7,500 test complaints. The test set is held out until final evaluation.

  • Checking or savings account
  • Credit card
  • Credit reporting or other personal consumer reports
  • Debt collection
  • Money transfer, virtual currency, or money service
  • Mortgage
  • Payday loan, title loan, personal loan, or advance loan
  • Vehicle loan or lease

The problem

Consumer financial complaint narratives contain information about the product involved, but categorizing large volumes manually can take time. This project treats categorization as an eight-class text classification task: given a cleaned complaint narrative, predict one of the eight selected CFPB product categories.

How it works

After filtering the selected categories and removing complaints without usable narratives, the modeling data uses cleaned complaint text and product labels. TF-IDF represents each narrative with up to 20,000 features, using unigrams and bigrams with a minimum document frequency of five.

Logistic Regression and XGBoost were evaluated with the same TF-IDF representation, and DistilBERT was fine-tuned as a transformer comparison. XGBoost was selected for production based on the performance and resource tradeoff, although DistilBERT had the higher validation Macro F1.

On the held-out test set, the final XGBoost model achieved 83.23% accuracy and 83.26% Macro F1. On the validation set, its Macro F1 was 83.35%; DistilBERT scored 85.09% but used 703.36 MB RAM in the recorded comparison, versus 88.77 MB for XGBoost.

The API provides health checking, single predictions, and batch predictions. A prediction returns a category and confidence score. The batch endpoint accepts up to 600 items.

Stack

Python, pandas, NumPy, scikit-learn, XGBoost, DistilBERT, FastAPI, Pydantic, Uvicorn, Docker, DVC, MLflow, GitHub Actions, GitHub Container Registry, and Render.

What I built

The documented workflow covers CFPB sample preparation, model experiments and comparison, error analysis, experiment tracking, and dataset and model versioning. The production TF-IDF and XGBoost pipeline is exposed through a FastAPI service, packaged in Docker, and deployed on Render.

GitHub Actions runs tests and linting, then builds and publishes the container image to GitHub Container Registry for deployment.

Challenges and what I learned

Model selection involved balancing validation performance against deployment resource use: DistilBERT had a higher validation Macro F1, while XGBoost was substantially smaller and used less RAM in the recorded comparison.

Error analysis found that short complaints were harder to classify: the reported error rate was 31.12% for narratives of 1–25 characters, compared with 10.71% for narratives over 500 characters. The largest reported validation confusion was between checking or savings account and money transfer complaints.

The model is limited to its eight trained categories; its confidence score is not a guarantee of correctness, and it is not intended to replace human review or make financial or legal decisions.
