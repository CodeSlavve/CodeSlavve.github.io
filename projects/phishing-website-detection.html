Phishing Website Detection

A Flask application that uses URL and hostname features to classify a site as legitimate or phishing.

Overview

The application accepts a URL and returns a classification, confidence, extracted URL features, and warning flags. The current API returns either Legitimate or Phishing; although the repository README mentions a “suspicious” class, the API's label map contains two classes.

For domains on its trusted-domain whitelist, the application returns a legitimate result without running the classifier.

The problem

Phishing URLs can use misleading hostnames, brand names, redirects, and URL structures. This project classifies a submitted URL using signals available in the URL and hostname, without fetching or inspecting the website's page content.

How it works

The feature extractor derives 35 values from the URL and hostname. These include URL length and structure, HTTPS and redirect signals, suspicious keywords and top-level domains, entropy, subdomain and path depth, URL shorteners, and brand-name/domain mismatches.

The API normalizes URLs without a scheme by adding http://, checks the trusted-domain whitelist, then scales the extracted features and runs the selected saved model. Random Forest is the default; Logistic Regression and SVM are also available.

POST /predict returns a result from one model, while POST /compare returns results from all three. Predictions include a confidence value and, when available, a phishing probability; the single-model response also includes extracted features and warning flags.

Stack

Python, Flask, pandas, NumPy, scikit-learn, and joblib. The repository includes notebooks for feature extraction and model training, and the web application is deployed on Vercel.

What I built

The repository contains the URL feature extraction pipeline, saved feature scaler and classification models, a Flask inference API, and a browser interface for checking URLs and comparing model outputs.

The interface presents the predicted label, confidence, warning flags, and extracted URL signals so the result includes the factors the application detected.

Challenges and what I learned

The model depends on the feature extractor, scaler, and saved models using the same feature definitions and order at training and prediction time. The application also bypasses model inference for whitelisted domains, so those results follow a separate rule.

The repository's README describes three possible labels, while the current API maps predictions to only Legitimate and Phishing. The project description reflects the behavior of the API code.
