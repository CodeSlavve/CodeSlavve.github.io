Samadhan Setu

An SIH 2026 prototype for reporting and routing civic challenges in Jharkhand. I built the AI layer that helps structure submitted issues for review and collaboration.

Overview

Samadhan Setu is a civic innovation portal prototype for Jharkhand. Citizens can submit and track local issues; university nodal teams and government administrators have workspaces for reviewing and managing them. The project also includes an issue map for viewing geolocated reports.

I built the AI layer, which processes new issue reports and returns structured information to the backend for persistence and downstream university routing.

The problem

Community-reported issues need to be understood, categorized, prioritized, and connected with people who can investigate or work on them. The prototype aims to connect citizen reports with university and government workflows, while making issue status and location visible in the portal.

How it works

When a citizen issue is created, the Spring Boot backend calls a separate FastAPI AI service; the browser does not call the AI service or Gemini directly. The AI pipeline handles Hindi/English language information, translation and summarization, classifies issues into one of ten domains, and produces a prototype priority result using rules.

For duplicate detection, the AI path can compare Gemini embeddings with FAISS similarity. If the external AI service is unavailable, the backend has deterministic fallback processing, including keyword-based classification, rule-based priority, and token/Jaccard comparison against candidate issues. Spring Boot then applies the analysis and performs category-based university routing.

The ten prototype domains are Education, Agriculture, Healthcare, Water Resources, Environment, Energy, Urban Development, Accessibility, Public Administration, and Rural Livelihoods.

Stack

React, Vite, Tailwind CSS, Leaflet, and Recharts for the frontend; Java 17, Spring Boot, Spring Data JPA, Spring Security, JWT, and MySQL for the backend; and Python, FastAPI, Gemini, and FAISS for the AI service.

What I built

I built the AI layer as a FastAPI microservice integrated through the Spring Boot AI bridge. Its prototype processing contract covers language handling, translation, concise summaries, ten-domain classification, confidence, rule-based priority with reasons, and duplicate-match information.

I also worked on the semantic duplicate-detection path using Gemini embeddings and FAISS, with a deterministic backend comparison fallback when the external AI call is unavailable.

Challenges and what I learned

A key design concern was keeping the AI service optional for the main issue workflow. The Spring Boot backend can generate deterministic prototype results when the FastAPI/Gemini path is unavailable, while keeping persistence and API access in the backend.

This is a prototype rather than a production AI platform: priority and university routing are rule-based, and the repository notes that the full deployed issue-to-AI-to-routing flow still needs runtime verification. Fine-tuned multilingual models, production vector infrastructure, and MLOps are outside the current implementation.
